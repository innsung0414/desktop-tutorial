**상태:** 첫 플레이 버전의 작업 기준 완성. 프로젝트 방향 중 사용자가 제공한 정보와 개발을 위해 임시로 정한 기본안을 구분합니다.

## 1. 목적과 표기

이 문서는 Deep Blue의 첫 플레이 버전에 필요한 목표, 범위, 조작, 기능 요구사항, 완료 조건, 기술 기준을 정의합니다. 연결된 실행 작업은 [TASKS.md](TASKS.md)에서 관리합니다.

표기 기준:

- **사용자 확정:** 사용자가 프로젝트 소개에서 직접 정한 내용
- **개발 기본안:** 작업을 시작할 수 있도록 우선 적용하는 권장안. 플레이 결과를 확인한 뒤 바꿀 수 있음
- **구현 현황:** 현재 프로젝트 파일에 있는 내용. Unity에서 실행 확인을 마치기 전까지 완료 동작으로 간주하지 않음
- **후속 범위:** 첫 플레이 버전 이후 검토할 내용

## 3. 제품 목표와 플레이어 경험

### 한 문장 소개

물가에서 낚싯줄을 던지고, 입질에 맞춰 챔질한 다음 줄의 장력을 조절해 물고기를 끌어올리는 3D 1인칭 낚시 게임.

### 첫 플레이 버전의 목표

플레이어가 실행 후 이동과 시점 조작을 익히고, 한 장소에서 캐스팅부터 물고기 획득 또는 실패까지의 낚시 과정을 반복해서 플레이할 수 있어야 합니다. 화면 안내와 새벽 호숫가 환경을 함께 제공하고, 플레이 결과에 따라 조작감과 표현을 다듬습니다.

### 대상 플레이어와 접근성 기준

- 낚시 게임을 처음 접해도 화면의 짧은 조작 안내를 보고 다음 행동을 알 수 있어야 합니다.
- 입질, 챔질 성공, 장력 위험, 낚시 결과는 화면 문구나 막대 등 시각 신호로 구분합니다.
- 첫 버전은 키보드와 마우스 조작을 사용합니다. 컨트롤러와 키 변경 메뉴는 후속 범위입니다.

## 4. MVP 범위

### 포함

- Windows PC에서 실행하는 싱글플레이어 빌드
- 한 곳의 물가와 걸어 다닐 수 있는 굴곡 지형, 소나무 숲·산·바위·부두·쉼터·벤치·랜턴
- 1인칭 카메라, 마우스 시점 회전, WASD 이동
- 낚싯대와 낚싯줄, 물 위의 찌를 표현하는 기본 시각물
- 캐스팅 힘을 조절하고 물 위 목표점에 찌를 보내는 동작
- 대기 중 입질, 제한 시간 안의 챔질, 성공/실패 피드백
- 물고기를 끌어올리는 장력과 진행도 상호작용
- 무료 Quaternius CC0 물고기 모델 35종과 Fish Alive 무료 샘플 2종을 합친 37개 수집 항목, 결과 화면, 같은 세션 안에서 다시 낚시하는 기능. 흰동가리 모델 두 개는 각각 클래식·Fish Alive 외형으로 구분
- 조작 안내, 입질 알림, 장력/진행 상태, 결과를 표시하는 최소 UI
- 물속에 연속으로 머물면 익사하는 위험 판정
- 타이틀, 일시정지, 음량·마우스 감도 설정, 조작법, 사망 후 재시작 메뉴
- 37개 물고기 모델 항목의 도감과 획득 횟수. 한 페이지에 6개씩 7페이지로 표시하며, 도감과 설정은 이 PC에 자동 저장
- 단계별 수집 목표(첫 물고기 → 서로 다른 3종 → 누적 5마리 → 도감 절반 19종 → 도감 80% 30종 → 전체 37종)와 달성 안내
- 어종별 게임용 무게 범위, 성공 결과의 무게·첫 발견·개인 최고 기록, 어종별 최고 무게 자동 저장
- 릴링의 안정/예고/저항 단계와 명확한 감기·쉬기 안내
- 카메라 시야 안에서 낚싯대 끝이 보이도록 낮춘 위치와 성공 순간 화면에 나타나는 어종별 3D 물고기
- 잡은 물고기를 보관함에 쌓고 판매해 화폐를 얻으며, 낚싯대와 찌를 사서 장착하는 간단한 낚시점

### 제외

- 여러 낚시 장소, 37개 항목을 넘어서는 추가 어종과 생태계 시뮬레이션
- 낚시점은 타이틀/일시정지 화면에서 여는 한 곳짜리 메뉴로 한정합니다. 물가의 실내 상점, 복잡한 가격 변동, 장비 강화 트리, 이야기 퀘스트, 레벨 및 장기 진행도는 제외합니다. 기존 도감 기록에서 계산하는 짧은 수집 목표는 포함
- 계정, 클라우드 저장, 온라인 기능과 멀티플레이
- 모바일/콘솔 빌드, 컨트롤러 조작, 키 설정 메뉴
- 최종 수준의 캐릭터 애니메이션, 완성형 시네마틱, 성우 녹음
- 유료 상품, 광고, 출시 플랫폼 및 상업 출시 계획

제외 항목은 사용자가 범위를 넓히기로 결정하기 전까지 MVP 작업으로 추가하지 않습니다. 무료 에셋 번들에는 담수·열대·심해 외형이 함께 있어, 이 어종들은 Deep Blue의 수집 대상 어종으로 사용합니다. 본 버전은 개별 어종의 실제 서식지 시뮬레이션이나 장소별 출현 제한을 구현하지 않습니다.

## 5. 기본 조작

| 입력 | 동작 | 적용 상태 |
| --- | --- | --- |
| `W`, `A`, `S`, `D` | 앞, 왼쪽, 뒤, 오른쪽 이동 | 물가 걷기 |
| 마우스 이동 | 좌우 및 상하 시점 회전 | 일반 이동 |
| 마우스 왼쪽 버튼 누르기/놓기 | 캐스팅 힘을 충전하고 놓을 때 던짐 | 준비 상태 |
| `Space` | 입질 신호가 보일 때 챔질 | 입질 상태 |
| 마우스 왼쪽 버튼 누르고 있기 | 물고기를 감아 올림. 놓으면 장력이 내려감 | 낚싯바늘에 물고기가 걸린 상태 |
| 마우스 왼쪽 버튼 | 다음 낚시 시작 | 결과 상태 |
| `Escape` | 일시정지 메뉴 열기/복귀, 하위 메뉴에서 뒤로 | 플레이 및 메뉴 |
| `Tab` | 물고기 도감 열기/닫기 | 플레이 및 도감 |

동일한 왼쪽 버튼은 상태에 따라 캐스팅, 릴링, 재시작에 쓰입니다. 실행하면 타이틀에서 시작하고, 낚시 시작 시 커서를 잠급니다. `Escape`로 메뉴를 열면 커서를 풀고 낚시·이동·익사 시간을 정지합니다. 메뉴 복귀 클릭이 캐스팅으로 전달되지 않도록 입력 유예를 둡니다. 포커스를 잃으면 자동으로 일시정지합니다.

## 6. 핵심 플레이 흐름과 규칙

1. 플레이어가 물가에서 물을 바라보고 낚시를 시작합니다.
2. 왼쪽 버튼을 누르는 동안 캐스팅 힘이 충전됩니다. 버튼을 놓으면 찌가 플레이어 앞의 물 영역으로 날아갑니다.
3. 찌가 물에 닿으면 입질 대기가 시작됩니다. 입질까지 걸리는 시간은 매 회 달라집니다.
4. 입질 신호가 표시되면 `Space` 또는 왼쪽 버튼을 제한 시간 안에 눌러 챔질합니다. 이때 어종과 개체 무게가 결정됩니다. 놓치면 실패 결과를 표시합니다.
5. 물고기가 걸린 뒤 왼쪽 버튼을 누르고 있으면 릴이 감기며 낚기 진행도와 줄 장력이 증가합니다. 안정 단계 이후 0.75초 예고를 거쳐 강한 저항이 오며, 이때 감으면 장력이 빨리 올라갑니다.
6. 버튼을 놓으면 장력이 내려갑니다. 장력이 끝까지 차면 줄이 끊겨 실패하고, 진행도가 끝까지 차면 물고기를 낚습니다.
7. 성공 시 어종·무게·첫 발견/최고 기록·수집 목표 진행을 표시하고 저장합니다. 실패는 원인과 다음 시도의 행동을 안내합니다. 결과를 0.8초 표시한 후 왼쪽 버튼을 누르면 다음 캐스팅으로 돌아갑니다.

### 시작 구현을 위한 수치 기본값

아래 수치는 밸런스 확정값이 아니라 프로토타입의 시작값입니다. Inspector에서 쉽게 조정할 수 있게 구현합니다.

| 항목 | 시작값 |
| --- | ---: |
| 캐스팅 충전 최대 시간 | 2초 |
| 입질 대기 시간 | 3~8초 무작위 |
| 챔질 입력 유효 시간 | 5초 |
| 릴링 진행도 증가 | 왼쪽 버튼을 누르는 동안 초당 25% |
| 장력 증가 | 기본 초당 35% × 안정/예고 0.65 또는 저항 1.45 × 개체 크기 계수 0.85~1.15 |
| 장력 감소 | 버튼을 놓는 동안 초당 25% |
| 저항 변화 | 안정 1.6~2.4초 → 예고 0.75초 → 저항 1.0~1.5초 반복. 저항 중 릴 진행은 기본의 65% |
| 성공/위험 한계 | 진행도 100%면 성공, 장력 100%면 실패 |

수치 변경 시 `TASKS.md`의 밸런스 작업과 이 표를 함께 갱신합니다.

## 7. 기능 요구사항과 완료 조건

| ID | 기능 요구사항 | 완료 조건 |
| --- | --- | --- |
| FR-01 | 1인칭 시점 조작 | 낚시 시작/계속 시 커서를 잠그고 마우스로 좌우/상하를 둘러볼 수 있음. 카메라가 뒤집히지 않으며 `Escape` 메뉴에서 커서를 풀 수 있음. 포커스 전환만으로 시점이 갑자기 돌아가지 않음. |
| FR-02 | 지형 위 이동 | WASD 이동이 작동하고 플레이어가 바닥 아래로 떨어지지 않음. 보행 영역 외곽에서는 울타리 충돌로 이동을 막으며 부두의 물 진입 통로는 유지함. |
| FR-03 | 기본 낚시 장소 | 플레이어가 안전하게 서서 물을 바라보고 찌의 착수 위치를 알아볼 수 있음. |
| FR-04 | 캐스팅 | 누른 시간에 따라 캐스팅 힘이 달라지고, 놓으면 찌와 줄이 실제 수면에 표시됨. 지형/바위와 겹치는 착수점은 최대 4m 안의 열린 수면으로 보정하며 찾지 못하면 안내 후 재시도할 수 있음. |
| FR-05 | 입질 대기와 신호 | 찌가 착수한 뒤 입질 대기 상태가 되며 입질 순간에 시각 안내가 나옴. |
| FR-06 | 챔질 | 입질 신호가 뜬 뒤 5초 안에 `Space`를 누르면 낚시 진행 상태로 이동하고, 왼쪽 마우스 클릭도 대체 챔질 입력으로 허용함. 놓치면 실패를 표시함. |
| FR-07 | 릴링 | 누르는 동안 진행도가 오르고 장력이 증가하며, 놓으면 장력이 감소함. |
| FR-08 | 결과 판정 | 진행도 100%는 물고기 획득, 장력 100%는 줄 끊김 실패로 구분됨. |
| FR-09 | 반복 플레이 | 성공과 실패 뒤 다시 캐스팅할 수 있고, 한 번 실행한 상태에서 3회의 낚시를 연속으로 시작할 수 있음. |
| FR-10 | 플레이 안내 UI | Canvas HUD에 준비/캐스팅/입질 대기/챔질/릴링/성공·실패 안내와 관련 진행 막대가 상태에 맞게 표시됨. 익사 카운트다운과 사망 화면도 제공함. |
| FR-11 | 물고기 보상 종류 | 37개 항목 중 한 종을 선택하고, 성공 결과에 해당 항목의 이름·도감 그림·애니메이션 3D 모델을 표시함. 도감 그림은 512×512 이상 크기의 선명한 이미지여야 하며, 썸네일 확대에 따른 픽셀 깨짐이나 투명한 빈 그림이 없어야 함. 35개 Quaternius 모델과 구피·흰동가리 Fish Alive 모델 모두 실제 보상으로 선택 가능해야 하며, 실패하면 물고기 보상을 표시하지 않음. |
| FR-12 | 익사 판정 | 물 판정 영역에서 연속 10초를 보내면 사망하고, 시간이 끝나기 전에 영역을 벗어나면 카운트다운이 초기화됨. 사망하면 플레이어와 낚시 조작이 멈춤. |

## 8. 기술 및 프로젝트 기준

- Unity `6000.3.12f1 LTS`, URP 사용
- 현재 패키지 설정: Input System `1.19.0`, URP `17.3.0`
- 입력은 Unity Input System을 사용합니다. 기존 이동/시점 코드가 `Keyboard.current`, `Mouse.current`를 직접 읽으므로 새 입력 액션 맵을 추가할 때는 두 방식을 혼용하지 않도록 정리합니다.
- 1인칭 이동은 `CharacterController`를 사용합니다. 플레이어 몸체와 카메라 상하 회전을 분리합니다.
- 낚시 흐름은 명시적 상태 전환으로 구현합니다: `준비 → 캐스팅 → 입질 대기 → 입질 → 릴링 → 성공/실패`.
- 입력 처리, 낚시 진행 규칙, 화면 표시를 한 스크립트에 모두 넣지 말고 책임을 나누되, 초보자가 따라갈 수 있는 작은 단계로 구성합니다.
- 환경은 Editor 생성 메쉬, URP 재질, imagegen 텍스처를 사용합니다. 쉼터는 배경 구조물이며 상점·출입 기능은 포함하지 않습니다. 물고기 모델은 Quaternius CC0 35종과 Fish Alive 무료 샘플 2종을 사용합니다.
- 환경 재생성 전 씬 백업을 남기고, 실제 Game 뷰에서 시각적 틈과 낚시/물 판정 간섭을 확인합니다.
- 낚시 플레이용 주 장면 목표는 `Assets/Scenes/DeepBlueFishing.unity`입니다. 장면 생성이 확인되기 전까지는 원본 `Assets/Scenes/SampleScene.unity`를 보존합니다.
- 낚싯대 시야 위치는 장면 생성기 기본값과 실행 시 장비 배치 모두에 반영합니다. 35개 Quaternius 원본 모델·컨트롤러는 `Assets/Archive/QuaterniusFish/`에 두고, 실행 프리팹은 `Assets/Resources/DeepBlueFish/Prefabs/`에서 불러옵니다. 구피·흰동가리 실행 프리팹은 `Assets/Resources/DeepBlueFish/FishAlive/`에 둡니다. 이전 12개 도감 ID와 기록은 현재 37개 항목과 분리해 보존합니다. 배경 음악은 사용자가 별도로 요청할 때 추가합니다.
